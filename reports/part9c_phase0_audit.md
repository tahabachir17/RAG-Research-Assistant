# Part 9c — Phase 0 Audit

Date: 2026-08-13

This audit records the repository and local-artifact state before the Part 9c
implementation changes. No remediation code was changed before this report was
created.

| Issue | Status | Evidence | Root Cause |
| --- | --- | --- | --- |
| Qdrant collection gap | **Partially confirmed** | The original Part 9 smoke path was BM25-only, as preserved in `evaluation/build_retrieval_diagnostic_report.py:431`. Current full-eval defaults instead request `evaluation/data/external_benchmarks/qdrant` and `bench_external_chunks` (`evaluation/run_full_ragas_eval.py:530-534`). Local inspection on 2026-08-13 found both `external_benchmark_chunks` and `bench_external_chunks`, each with 2,777 points. QASA and QASPER share this collection; SciDQA emits no evaluation rows. `DenseRetriever.search` raises for a missing/empty collection (`retrieval/dense_retriever.py:99-106`), so current dense/hybrid execution does not silently fall back. Sparse mode is an explicit CLI choice (`evaluation/run_full_ragas_eval.py:111-114`). | Historical evaluation orchestration directly used the external BM25 index and never constructed the production retrieval stack. The current code fixed the path/configuration but has no explicit evaluator startup check covering every selected external tier before model loading/retrieval; failure occurs only when dense search performs its health check. |
| Judge schema mismatch / four remaining anomalies | **Partially confirmed** | Raw captures are preserved in `evaluation/data/eval_results/retrieval_stack_diagnostic_20260812/judge_reliability.json`. Of six selected anomalies, two invalid faithfulness cases exercised multi-stage JSON parsing and four cases remained after the diagnostic. `gen-003` was repaired; `gen-005` remained invalid. Its strict 8B JSON-mode output ended without completing the requested RAGAS shape at the 1,024-token diagnostic budget, so it shows **both truncation and schema-shape mismatch**. The three remaining answer-relevancy hard-zero cases (`qasa-1409.0575-1`, `qasper-32a232...`, `qasper-bf0080...`) returned complete, schema-valid `{question, noncommittal}` objects; they are semantic noncommittal verdicts, not broken JSON calls. The existing parser patch in the dirty working tree (`evaluation/ragas_evaluator.py:344-449`) already attempts wrapper recovery, but the full runner currently defaults away from the requested 8B judge (`evaluation/run_full_ragas_eval.py:483-497`) and lacks token-cap escalation based on truncation. | JSON Object Mode guarantees JSON syntax, not the legacy RAGAS top-level schema. Long faithfulness records can exceed 1,024 tokens. Three of the “four remaining” anomalies are judge-semantic behavior caused by answers explicitly saying evidence is unavailable, not schema failures. |
| Full retrieval stack exercised | **Partially confirmed** | The 75-question Part 9b ablation invoked dense, sparse, RRF fusion, cross-encoder reranking, and MMR once per question; the call sequence and timings are recorded by `evaluation/retrieval_evaluator.py:115-147`, and `retrieval_diagnostic.json` contains 75 rows per configuration (375 configuration rows). The actual earlier Part 9 smoke was BM25-only (`evaluation/build_retrieval_diagnostic_report.py:431`). The current full runner supports dense, sparse, hybrid RRF, and hybrid rerank (`evaluation/run_full_ragas_eval.py:24-29`, `91-176`) and defaults to hybrid rerank, but it explicitly records `mmr: false` (`evaluation/run_full_ragas_eval.py:405`). | The diagnostic and full RAGAS runners diverged: MMR was implemented only in the ablation evaluator, not in the production-style full benchmark path. |
| MMR at small k | **Confirmed** | On the reviewed 75-question QASA/QASPER set with lambda=0.5, reranked Recall@4 was 0.4571 and Recall@8 was 0.6146; adding MMR reduced them to 0.1800 and 0.3108. Effect sizes were **-0.2771 at k=4 (-60.6%)** and **-0.3038 at k=8 (-49.4%)**. Recall@20 was unchanged at 0.6946 because MMR selected all 20 candidates. Source: `evaluation/data/eval_results/retrieval_stack_diagnostic_20260812/ablation.csv:5-6`. | MMR was applied after reranking with `final_k=20`, then the reordered list was evaluated at smaller cutoffs. Lambda=0.5 over-prioritized diversity and displaced highly relevant top-ranked evidence at the generator’s real k=4 boundary. |
| Reranking latency | **Confirmed** | The 75-query ablation measured hybrid RRF at 119.9 ms/query and hybrid+rerank at 28,439.7 ms/query, so reranking added about 28.32 s and represented **99.6%** of the reranked pipeline latency (`ablation.csv:4-5`). The focused profile in `reranker_latency.json` measured 20 candidates at 8.021 s cold / 6.925 s warm and 50 candidates at 16.860 s cold / 16.835 s warm; an 8-thread sweep reached 5.899 s for the profiled batch. The stored artifact has only aggregate means and focused samples, so a defensible per-query p50/p95 is not yet available and must be produced in Phase 4. | CPU cross-encoder inference dominates. Candidate-set size is the primary lever; threading helps but does not remove the bottleneck. |
| `qasper-bf0080...` | **Not reproducible as an ingestion gap** | `evaluation/data/external_benchmarks/qasper_generation_qa.json:27-32` marks the row unreviewed, with reference answer “The question is unanswerable from the paper,” no reference context IDs, and no frozen retrieved IDs. The upstream QASPER annotation itself is unanswerable and supplies no evidence. All five retrieval configurations miss reviewed evidence only because none exists (`failure_correlation.json`). | This is a corpus-label limitation, not a missing chunk or ranking miss. It should remain non-score-blocking through the existing unavailable-metric rules rather than trigger ingestion changes. |
| SciDQA zero emission | **Confirmed** | Live normalization of the cached export produced 2,937 rows, selected 0, and counted `missing_evidence: 2937`. The export fields are `id, year, venue, rid, pid, decision, que, ans, version`; there is no evidence/context field. `sample_scidqa` rejects rows without evidence (`evaluation/external_benchmarks.py:317-332`), and the full evaluator skips the empty tier (`evaluation/full_ragas_evaluation.py:73-77`). | The selected upstream SciDQA export has questions/answers but no grounding passages or evidence spans. This cannot be repaired truthfully in the adapter alone; obtaining/linking source documents is an ingestion-side change and is out of scope. |

## Audit decision

Proceed with explicit Qdrant preflight, an 8B-first schema-validating judge path with
truncation-aware token escalation and resumable metric caching, and config-gated
MMR disabled below the evidenced harmful cutoff. Treat `qasper-bf0080...` and
SciDQA as documented corpus limitations. Do not change the default reranker
configuration until the candidate-size latency/recall comparison is measured.
